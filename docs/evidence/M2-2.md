## Acceptance and transition contract

Both editions must create/reopen/revise notes; explicitly confirm and durably retain memories; set temporary expiry; supersede with same-workspace acyclic successor; archive/restore without deleting; compare and restore historical content as a new revision after both processes restart. Default lists omit archived and expired records, with explicit opt-in filters. History remains available. Creation time, privacy and origin survive restoration. No model call or new browser capability.

| From | Allowed explicit targets |
|---|---|
| Proposed | Confirmed, Temporary, Archived |
| Confirmed | Proposed, Temporary, Durable, Superseded, Archived |
| Temporary | Proposed, Confirmed, Durable, Superseded, Archived |
| Durable | Proposed, Confirmed, Temporary, Superseded, Archived |
| Superseded | Archived |
| Archived | Prior state through restore-archive only |

Same-state transitions and every omitted pair are rejected. Content edits preserve state and provenance. Durable requires prior confirmation or an explicitly user-selected Temporary record; Proposed cannot silently become Durable. Entering Temporary requires a future UTC expiry; expiry never deletes data. Restoring an expired archived record retains its expired visibility. Valid-until applies to list visibility for every state, including Durable; retention is not a claim of current factual validity.

Supersession is a forward successor pointer on the old record, separate from the reserved supersedes predecessor field. Archive retains successor edges and restores the exact previous state. All graph validation runs under the SQLite publication lock to reject simultaneous cycles. Wrong-workspace successors return the same unavailable-record error as missing records. No automatic edge removal or record deletion.

Historical restore copies text, title, event/validity dates, confidence and source references as a new revision; current privacy, state, creation and provenance/generator metadata remain intact. It never reconfirms old generated content. Expected revision is mandatory for every edit/action/restore. The UI shows both selected and current content and explains restoration before the explicitly named restore button.
