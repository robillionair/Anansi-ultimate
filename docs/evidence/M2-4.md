## Acceptance criteria defined before implementation

1. SQLite persists all six job states, optimistic versions, owner leases, bounded progress/checkpoints, fixed safe logs and visible resource limits. Competing workers cannot publish the same attempt. Expired Running jobs become Paused; resume/retry is explicit.
2. Explicit workspace, project or record selection exports a consistent catalog snapshot, all selected revision bodies and hashes, metadata, provenance, privacy and relationship history in open Markdown and versioned JSON. Relationships crossing the selection boundary retain opaque references without exporting other records. Project selection includes the project and records currently assigned to it; historical outside references are documented rather than silently importing unrelated records.
3. Export refuses Sealed current or historical records; it never follows links, renders source HTML, fetches remote resources, accepts browser paths, logs content or publishes partial files. Limits: 10,000 records and 256 MiB total archive bytes, including metadata/history.
4. Cancellation and lease fencing prevent publication; failures retain private unreferenced files for recovery. Retry rebuilds an idempotent snapshot stage using a new attempt and artifact identity. No destructive cleanup or product restore is introduced.
5. Only an owned completed artifact can be read. Browser receives bounded chunks and explicitly downloads a standard uncompressed TAR containing Markdown and JSON. Native retrieval remains in managed private storage until a trusted save operation explicitly selected by the user.
6. Tests cover migration, ownership, races, expiry, all states, cancellation/retry/restart, integrity, quota and filesystem failures, hostile source text and Sealed refusal. Existing documentation, contract, Rust, UI, browser and native checks must actually run. Actual cross-adapter export verification must inspect downloaded files and restart recovery.

## Implementation and honest limits

- Schema 7 is forward-only; migrations 1–6 are unchanged. Historical migration fixtures now remove the future jobs table when representing older catalogs; failed-migration rollback checks remain enforced.
- New jobs have only the real export handler. No fake indexing, AI, backup or connector handlers are registered. Six states, optimistic controls, a private 120-second owner lease, versioned stage checkpoints, fixed safe logs and explicit resource bounds are implemented.
- Project/workspace/record selections retain every selected revision and internal edge revision. The version-1 manifest keeps the full original metadata, provenance, privacy, hashes and current pointers. Crossing relationships retain opaque IDs rather than exporting sensitive metadata from an unselected endpoint. System TAR extraction independently confirmed the container format in the browser workflow.
- Retry/resume rebuilds the idempotent snapshot stage with a new artifact ID. The record counter is progress information, not byte-level continuation. Expired Running jobs pause until explicit resume. Real process termination is included in the expanded test suite; the isolated synthetic lease timestamp is advanced for expiry rather than waiting two minutes.
- Files are synced before a fenced completion transaction publishes ownership. Unfinished files stay private and unreferenced; no cleanup/purge or automatic recovery import is added. Owned complete artifacts are fetched in 64 KiB chunks. Browser and native saves verify the final SHA256 before publishing a destination file.
- Filesystem failure tests use a non-directory destination and a real write through a read-only handle. Byte/record quota tests exercise explicit refusal; no physical disk was filled. Private is plaintext, including exported source references. Sealed current and historical revisions are refused.
- Initial development failures were repaired: SQL integer conversion, generated multiline union deduplication, navigation button expectations and sanitized shared NotFound wording. These are covered by subsequent static/UI checks. The native rerun passed after the repairs below.

M2.5 backups and product restore, vault design/implementation and later milestones remain unstarted by this task. No new dependency or lockfile change. No M2 completion tag.

## Repairs found by executed verification

- The initial Windows execution-policy refusal was repaired without changing machine policy: the verifier evaluates its tracked helper through a fixed command. Providers also exposed controls without UIA patterns. The helper now validates the exact owned dialog process, child handles, classes and IDs, uses bounded [edit selection](https://learn.microsoft.com/en-us/windows/win32/controls/em-setsel)/[replacement](https://learn.microsoft.com/en-us/windows/win32/controls/em-replacesel) messages, reads the selected path back and activates only the owned Save button. An isolated check caught that setting display text alone did not update the dialog's selected filename; replacement notifications fixed this before the real save was accepted.
- A real cross-adapter assertion caught stale job-list correlation: both exports were correct in SQLite, but counting list rows could select the earlier native job. The interface now retains the acknowledged new job ID, returns to the newest page and marks the latest request; verification follows that exact owned row. Expected project/content assertions were preserved.
- A worker shutdown race could lose the last wake-up. A single synchronized pending-root queue now pairs notifications with stop decisions. Headless multi-root and authenticated retry tests complete without UI/list commands waking them.
- An owned dialog from a failed verification survived its desktop parent. It was identified by its recorded parent PID and exact dialog source, then stopped. The production dialog now monitors its actual Rust parent and exits when that parent terminates; final native verification explicitly tests this before running cleanup. The verifier also closes only known owned dialog children on failure.
- Native captures now remain under the synthetic verifier root rather than the browser suite's resettable output directory. Final capture/view inspection is pending.
