## Architectural design and verified safety boundaries

1. **End-to-End Browser & Native Workflow Parity**:
   - `tests/e2e/ask_anansi.spec.ts` exercises the complete browser application interacting with `anansi-api` over authenticated loopback HTTP API (`/v1/ai/discovery`, `/v1/ai/ask`) and validates identical data models shared with native desktop IPC (`ai_command`).
   - Workspaces, settings, structured records (decisions, notes, tasks), search indexes, runtime discovery, and Ask ANANSI interface are verified live in the headless Chromium browser.
   - Zero external requests policy: network interceptor verifies `external === 0` across the entire workflow; no network calls leave `127.0.0.1` / `localhost`.

2. **Truthful Missing-Evidence & Anti-Hallucination**:
   - When asked questions without matching workspace records (e.g., query for planetary space exploration in an architecture workspace), the engine:
     - Returns `AskStatus::InsufficientEvidence`.
     - Leaves citations empty.
     - Emits truthful guidance explaining that no relevant memories or notes were found.
     - Logs routing reason `"insufficient_evidence"`.
     - Never fabricates or hallucinates ungrounded information.

3. **Grounded Citations with Heading & Line Locations**:
   - When asked questions with matching workspace records (e.g., "What did we decide about local search?"):
     - FTS5 query extraction isolates content keywords.
     - Compiles ranked evidence pack citing `# Architecture Plan` (line 3) from the matching decision document.
     - In offline mode (no Ollama/LM Studio instance running on loopback), gracefully transitions to `AskStatus::Offline`.
     - Returns structured citation cards with index, title, kind, section heading, line number, and snippet.
     - Renders actionable offline status banner guiding the user to start a local server.

4. **Data Disclosure Manifest ("View What ANANSI Sent")**:
   - The user can inspect the full transparent disclosure payload before or after model invocation:
     - Runtime kind (`ollama`, `lmStudio`, `customLoopback`).
     - Loopback endpoint address (`http://127.0.0.1:11434`).
     - Model tag (`llama3.1:8b-instruct-q4_K_M`).
     - Source memory references (`id`, `title`, `kind`).
     - Character count (e.g. 520 chars) and estimated tokens (~130 tokens).
     - Exact compiled prompt text sent to the local inference runtime.

5. **Coordinated Fail-Closed Sealed Privacy Boundary**:
   - Master Spec §74, §78:
     - Sealed memories are strictly excluded from the FTS5 full-body search index (`WHERE privacy != 'sealed'`).
     - `crates/core/src/ask.rs` enforces defense-in-depth via `SearchBoundary::may_index(meta.privacy)`.
     - Vault invalidation tests (`crates/core/tests/vault_search_invalidation.rs`) verify that sealing or revoking a record removes its plaintext canary transactionally.
     - Unauthenticated browser endpoints cannot create or access Sealed records.
