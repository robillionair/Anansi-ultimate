## Design and acceptance before implementation

Shared Rust workspace service provides list/create/open/update-settings through authenticated HTTP and a scoped native command. Exactly one trusted configured storage root is used by both editions: ANANSI_STORAGE_ROOT at process launch, otherwise LOCALAPPDATA/ANANSI/workspaces on Windows or HOME/.local/share/anansi/workspaces on Unix. Browser requests contain only workspace labels/IDs and a boolean setting; paths are not accepted. The shared chooser lists managed IDs; native permission allow-workspaces authorizes only this bounded service, not an OS filesystem picker.

The owned root contains .anansi-root and workspaces.sqlite3. Initialization happens only on an explicit create action and claims only a new/empty directory. Unknown nonempty directories, repository ancestors, relative/parent-traversal roots and link/reparse paths are rejected. Existing root and database permissions are verified on every operation; ACLs are only applied during explicit initialization. Windows uses owner-only protected ACLs, read back through a tracked trusted helper; Unix uses 0700/0600. No guarantee against administrators or malicious same-user filesystem races is claimed.

One versioned catalog stores stable OS-random 128-bit workspace IDs, labels and a foreign-key-linked settings row. Migration 0001 creates STRICT tables in a transaction and commits application_id/user_version with the schema. Operational connections enable foreign_keys, WAL and an explicit 5-second busy timeout. Existing catalog identity/version is inspected read-only before any read-write connection. Unknown/corrupt/newer files are preserved and produce recoverable errors; there is no automatic reset, overwrite, downgrade or delete operation.

Labels currently accept 1–64 ASCII letters/numbers/spaces/underscores/hyphens, start with an alphanumeric character, reject surrounding whitespace and reserved Windows device names, and are unique ignoring ASCII case. Labels and IDs never become paths. Reduced motion is persisted per workspace and actually suppresses CSS transitions/animations/smooth scrolling while that workspace is open; OS reduced-motion preference remains honored as well. Both clients share UI, DTOs, static validators and Rust validation. All filesystem/SQLite work runs on blocking worker threads behind the adapters.

Dependency verification: rusqlite 0.40.2 from crates.io/docs.rs, bundled libsqlite3-sys 0.38.2 (bundled SQLite header 3.53.2), exact Cargo resolution. No system SQLite installation. [Official connection/transaction API](https://docs.rs/rusqlite/0.40.2/rusqlite/struct.Connection.html), [SQLite WAL](https://www.sqlite.org/wal.html) and [PRAGMA reference](https://www.sqlite.org/pragma.html) consulted.

## Recovery and remaining scope

Source bundles do not contain private catalogs or build artifacts. Before manual data recovery, close both API and desktop; preserve the whole storage root, including any WAL/SHM files, outside Git. Keep the original unchanged and restore only from a known compatible verified copy. Do not copy just the main database while either process is running, delete unknown files, lower schema versions or remove a failed-initialization file automatically. A crash during the initial catalog claim can leave a preserved incomplete catalog and a recoverable failure; inspect/preserve it before any manual repair. Simultaneous first initialization can require retry; concurrent connections to initialized catalogs are tested separately.

Automatic application-data backup/restore remains M2/M15. Vault/encryption remains M2/M15. This task is workspace metadata/settings only; M1 is incomplete. Next after acceptance is M1.4.
