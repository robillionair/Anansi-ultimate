# M3.3 — Authorized Local AI Runtime Discovery and Hardware Profiling

Status: verified implementation. Acceptance criteria defined in [the detailed plan](../../plans/03-search-and-ollama.md) before code. Milestone 2 integration is maintained intact; pure Rust, p=4, and the G1 audit gate remain unchanged.

Acceptance scope: detect local AI runtimes (Ollama, LM Studio, and compatible loopback inference endpoints) and perform native hardware resource inspection (CPU architecture, logical cores, total/available physical RAM, disk available space, GPU acceleration/VRAM). Provide model recommendations scaled to detected capacity with strict offline resilience, user-chosen loopback configuration, explicit download consent requirements, and refusal of automatic model downloads or unprompted background inference.

Authority: Master Spec §7, §18–19, §67, §69–70; Requirements Matrix AN-009, AN-020, AN-026.

## Architectural design and safety boundaries

1. **Native Hardware Resource Profiling**:
   - `crates/core/src/ai_discovery.rs` implements hardware capability inspection without introducing heavy third-party system dependencies:
     - **CPU Architecture & Threads**: Captured directly via `std::env::consts::ARCH` and `std::thread::available_parallelism()`.
     - **System RAM (Total & Available)**: On Windows, queried via standard Win32 `GlobalMemoryStatusEx` (`kernel32.dll`), reporting accurate physical total and available bytes. Non-Windows environments provide standard dev/test fallbacks.
     - **Disk Free Space**: On Windows, queried via `GetDiskFreeSpaceExW` (`kernel32.dll`) against the storage root directory, reporting actual free disk storage available to the user.
     - **Graphics Acceleration**: On Windows, checks display adapter registry class (`SYSTEM\CurrentControlSet\Control\Class\{4d36e968-e325-11ce-bfc1-08002be10318}`) via `advapi32.dll` to detect discrete GPU name (e.g., NVIDIA GeForce, AMD Radeon) and dedicated video RAM (`qwMemorySize`). If discrete GPU detection is unavailable or denied, falls back safely to CPU-only without crashing or blocking.

2. **Loopback Probe and Strict Network Isolation**:
   - Master Spec §7 and §67 require local-first offline execution with zero cloud leakage:
     - Endpoints are probed using pure Rust standard library `std::net::TcpStream` with strict connect, read, and write timeouts (1.5s timeout, well under the 2s bound).
     - **Loopback Enforcement**: All probed URLs are strictly validated to loopback addresses (`127.0.0.1`, `localhost`, `[::1]`). Any external hostname or non-loopback IP (e.g. `api.openai.com`, `192.168.1.1`) is fail-closed rejected with `RuntimeStatus::Unsupported` without sending network traffic.
     - Default probes:
       - Ollama: `http://127.0.0.1:11434` (path `/api/tags`)
       - LM Studio: `http://127.0.0.1:1234` (path `/v1/models`)
     - Supports user-specified custom loopback ports via `customEndpoints` parameter.
     - When a local server is not running, the probe reports truthful `RuntimeStatus::Offline` in milliseconds without freezing the application.

3. **Hardware-Tiered Model Recommendations**:
   - Recommendations are dynamically computed according to system memory capacity:
     - **High-Capacity Tier (>= 16 GB RAM/VRAM)**:
       - `qwen2.5:14b-instruct-q4_K_M` (14B, Q4_K_M, min RAM 14 GB) -> `Recommended`
       - `llama3.1:8b-instruct-q4_K_M` (8B, Q4_K_M, min RAM 8 GB) -> `Comfortable`
     - **Standard Balanced Tier (8 GB – 16 GB RAM/VRAM)**:
       - `llama3.1:8b-instruct-q4_K_M` (8B, Q4_K_M, min RAM 8 GB) -> `Recommended`
       - `qwen2.5:7b-instruct-q4_K_M` (7B, Q4_K_M, min RAM 8 GB) -> `Recommended`
       - `qwen2.5:14b-instruct-q4_K_M` -> `Tight` (if available RAM is constrained) or `Insufficient`
     - **Constrained / CPU Tier (< 8 GB RAM)**:
       - `qwen2.5:1.5b` (1.5B, Q4_K_M, min RAM 2 GB) -> `Recommended`
       - `llama3.2:3b` (3B, Q4_K_M, min RAM 4 GB) -> `Recommended`
       - Larger models -> `Insufficient` or `Tight`
   - Every recommendation contains clear parameters: model tag, parameter size, quantization level, minimum RAM requirement, descriptive purpose, and `fitLevel` badge (`recommended`, `comfortable`, `tight`, `insufficient`).

4. **Explicit Governance and Consent Boundary**:
   - Master Spec §69–70, AN-009, AN-020, AN-026:
     - `downloadConsentRequired` is permanently returned as `true`.
     - Probing never initiates automatic model pulling, downloading, or cloud telemetry.
     - UI presents explicit command line instructions (e.g. `ollama run <model>`) rather than auto-executing background downloads.
     - The user retains total authority over which model to download and run.

5. **Cross-Edition Contract & UI Integration**:
   - **Rust Core & Tauri**: Exposed via `Core::ai_command("discovery", ...)` and Tauri command `ai_command`.
   - **Web API**: Exposed via `/v1/ai/discovery` on the authenticated HTTP server.
   - **TypeScript Client**: Typed DTOs generated via JSON Schema (`AiDiscoveryRequest`, `AiDiscoveryResponse`, `HardwareProfile`, `DiscoveredRuntime`, `ModelRecommendation`).
   - **UI**: Dedicated "SYSTEM -> Local Models" view displaying system capabilities, detected local inference engines, installed models, custom loopback testing, and recommended model cards with explicit consent disclosures.
