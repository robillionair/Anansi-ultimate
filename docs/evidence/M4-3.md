## Architectural design and safety boundaries

1. **Dual-Modality Retrieval Pipeline (`hybrid_search`)**:
   - `crates/core/src/hybrid.rs` implements a unified retrieval pipeline combining keyword matching and vector semantics:
     - **Lexical Branch**: executes SQLite FTS5 BM25 search over `memory_body_fts` when a text query is present. Extracts grounded citations (enclosing Markdown `# Heading` and line number) using `locate_evidence`.
     - **Semantic Branch**: executes cosine similarity search over `memory_embeddings` via `vector_search` when a query vector and model tag are present.
     - Candidate records from both modalities are combined into a deduplicated candidate set.

2. **Reciprocal Rank Fusion (RRF)**:
   - Evaluates combined relevance without requiring score calibration or normalization between unbounded BM25 scores and $[-1.0, 1.0]$ cosine similarities:
     $$\text{RRF Score}(d) = \sum_{m \in \{\text{lex}, \text{sem}\}} \frac{w_m}{k + \text{rank}_m(d)}$$
   - Parameter $k$ defaults to $60.0$ (configurable, bounded $\ge 1.0$).
   - Configurable weights: $w_{\text{lex}}$ (`lexical_weight`) and $w_{\text{sem}}$ (`semantic_weight`).
   - Results are sorted descending by RRF score, breaking ties stably by `memory_id`.

3. **Metadata, Entity, and Privacy Boundaries**:
   - **Fail-Closed Sealed Privacy**: `memories.privacy` is checked; records marked `"sealed"` are strictly omitted from hybrid search results even if present in either lexical or vector index.
   - **Archive Boundary**: archived records (`archived != 0`) are excluded unless `include_archived: true` is explicitly requested.
   - **Kind Filter**: optional record kind filter (`kind`) restricts matches to requested knowledge kinds (e.g. `decision`, `note`, `task`).
