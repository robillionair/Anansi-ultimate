# M1.4 — First-run, navigation and shared accessible design

## Acceptance defined before implementation

Scope is the approved M1.4 task, master sections 7–8, 63–64, 70–71, 74–75 and 82–84. Preserve the master specification. Stop before M1.5 or M2.

- A new user chooses any of the five specified intents, creates or opens a local workspace, reviews the actual privacy limits, skips unavailable AI setup and enters a usable workspace.
- Intent is changeable in settings. Intent and onboarding completion persist per workspace alongside reduced motion, through the same Rust service and generated native/HTTP contracts. No cloud authorization is implied by onboarding.
- Forward schema migration preserves existing version-1 workspace IDs, names and settings; test rollback, unsupported versions and restart behavior. Existing catalogs are never reset.
- Shared navigation exposes a small working set (workspace, settings, connection) and the specification's grouped future tools as clearly unavailable, with no fabricated dashboard or provider/hardware success.
- Actual browser and Windows desktop workflows verify first run, reopening, settings, keyboard/focus, accessible names, narrow/wide layouts, reduced motion and recoverable errors. Offline first run needs only the local service/bundled application; no fonts, telemetry, model downloads or provider requests.
- Run component rendering tests, core/contract tests, browser E2E, native cross-adapter verification, builds, foundation checks, docs/coverage validation and protected checkpoint CI. Inspect actual screenshots. Record only executed outcomes.
