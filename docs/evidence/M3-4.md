# M3.4 — Minimum Context Compiler and Local Ask ANANSI Query Pipeline

Status: verified implementation. Acceptance criteria defined in [the detailed plan](../../plans/03-search-and-ollama.md) before code. Milestone 2 integration is maintained intact; pure Rust, p=4, and the G1 audit gate remain unchanged.

Acceptance scope: deterministic minimum Context Compiler and local Ask ANANSI query pipeline. Grounded queries compile evidence packs from authorized plaintext records, enforce strict context budgets (max 4,000 characters / ~1,000 tokens), deduplicate overlapping sources, generate an inspectable "View What ANANSI Sent" disclosure manifest, refuse hallucination on missing evidence, and execute local loopback inference via Ollama (`/api/generate`) and LM Studio (`/v1/chat/completions`) with robust offline fallback.

Authority: Master Spec §11, §13, §16–19, §66–67, §71, §74, §78, §84; Requirements Matrix AN-006, AN-009, AN-010, AN-018, AN-029.

## Architectural design and safety boundaries

1. **Deterministic Minimum Context Compiler**:
   - `crates/core/src/ask.rs` implements `Core::ask_anansi(request: AskRequest)`:
     - **Query Extraction**: Extracts content terms, stripping common English stop words ("what", "did", "we", "decide", "about", "the", etc.) while preserving specific search terms.
     - **Full-Body FTS5 Search**: Executes workspace body search for top matching active records.
     - **Fail-Closed Privacy Boundary**: Sealed records are permanently excluded before compilation.
     - **Deduplication**: Records flagged as duplicates (`duplicate_of.is_some()`) are skipped to eliminate redundant context tokens.
     - **Strict Context Budget**: Bounded to 4,000 characters (~1,000 tokens). Items that would exceed the 4,000 character limit are omitted, guaranteeing the context fits comfortably within small local LLM context windows (1.5B/3B/8B).
     - **Structured Grounded Citations**: Each citation contains `index` (1-indexed), `memory_id`, `title`, `kind`, `section_heading`, `line_number`, and exact `snippet`.

2. **Truthful Missing-Evidence Response**:
   - If 0 matching records are found in the workspace:
     - Returns `AskStatus::InsufficientEvidence`.
     - Citation list is empty.
     - Explanatory answer: *"I couldn't find any relevant memories, notes, or knowledge records in this workspace to answer your question. Add a note or memory with the relevant information first."*
     - Manifest routing reason is marked `"insufficient_evidence"`.
     - Zero tokens or external calls are wasted. Never hallucinates an ungrounded answer.

3. **Offline Resilience**:
   - When local inference engines (Ollama or LM Studio) are offline, unstarted, or unreachable:
     - The system gracefully catches connection refusal / timeout and returns `AskStatus::Offline`.
     - Returns the compiled citations, source references, and full prompt disclosure manifest.
     - Guides the user to start a local server (`ollama run llama3.1:8b` or LM Studio local server).
     - Never crashes, never throws an unhandled error, and never leaks data to remote cloud services.

4. **100% Loopback Inference & Security**:
   - Master Spec §7, §67, §78:
     - Supported inference runtimes: Ollama (default `http://127.0.0.1:11434`, path `/api/generate`) and LM Studio (`http://127.0.0.1:1234`, path `/v1/chat/completions`).
     - Loopback Validation: Endpoints are strictly validated to loopback addresses (`127.0.0.1`, `localhost`, `[::1]`). Any external URL (e.g. `http://api.openai.com`) is rejected with `ErrorCode::InvalidRequest`.
     - Loopback HTTP POST uses pure standard library `std::net::TcpStream` with strict 30-second connect/read/write timeouts.

5. **Data Disclosure Manifest ("View What ANANSI Sent")**:
   - Master Spec §69–70, §84:
     - `DisclosureManifest` returned with every Ask response provides full transparent accounting:
       - `runtimeKind`: `"ollama"`, `"lmStudio"`, or `"customLoopback"`
       - `endpoint`: loopback URL
       - `modelTag`: exact model invoked
       - `sourceMemories`: list of `{ id, title, kind }`
       - `characterCount`: character length of compiled prompt
       - `estimatedTokens`: token estimate (chars / 4)
       - `routingReason`: `"local-first offline inference"`
       - `compiledPrompt`: exact text of the prompt sent to the model

6. **Cross-Edition Contract & Shared UI**:
   - **Rust Core & Tauri**: Registered `ai_command` operation `"ask"`.
   - **Web API**: Exposed via authenticated POST route `/v1/ai/ask`.
   - **TypeScript Client**: Generated JSON schemas (`AskRequest`, `AskResponse`, `GroundedCitation`, `DisclosureManifest`) and client method `client.askAnansi(workspaceId, prompt, options)`.
   - **Shared UI**: `packages/ui/src/AskAnansi.tsx` rendered under `HOME -> Ask ANANSI` in `Navigation.tsx` and `Workspace.tsx`. Features prompt input (max 500 chars), answer box, citation pill list, and collapsible "View What ANANSI Sent" disclosure details.
