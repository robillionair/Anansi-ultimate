## ADR-0026: Explicit schema-9 vault core and transactional generation authority

Owner-authorized M2.7-Core Increment 2 is isolated from M3 Search/UI/adapters/workflows. It adds an explicit core API, not an automatic live migration. Ordinary Core remains schema 8 and refuses schema 9; schema-9 triggers reject stale plaintext writers. A verified matching M2.5 snapshot and recovery acknowledgement precede the initial whole-workspace cutover. No partial selection or plaintext truncation is inferred.

OS root locks and a shared configured private host/user KDF namespace admit operations. Synced authenticated generation files precede an immediate SQLite transaction committing active generation, opaque membership/file inventory and durable epoch. Old generation is authoritative before commit, new generation after commit; errors from post-commit observers cannot imply rollback. Explicit authenticated rollback is a new epoch-advancing transaction. Old slots/generations, source backups/body files, database remnants and interrupted staging remain preserved. This is not forensic erasure or certified full at-rest conversion of previous copies.

Record metadata/history and graph revisions are typed authenticated payloads. Opaque inventory permits locked ciphertext backup without exposing per-record revision mappings; coarse identifiers/file counts/lengths still leak. Fresh restore verifies all members, assigns fresh IDs and keys and retains origin mappings. Recovery activation needs a private receipt after saved-copy consent, one-time display challenge and actual recovery-slot unwrap. All live Sealed commands stay refused until coordinated integration and native/browser acceptance. [Increment 2 evidence](evidence/M2-7-increment2.md) records tests and limitations. G1-External-Audit remains open under ADR-0025; no audit is replaced by tests.

## ADR-0008: Independent committed-source bundle recovery

- Decision: backup-source.ps1 requires an explicit absolute .bundle destination with an existing parent outside the checkout, Git dir/common dir and .git ancestry. Reject existing destinations, reparse-point/symlink/junction ancestors, shallow/empty history and any tracked/untracked worktree change. Use native argument arrays, check every Git exit code, stage a unique external bundle, verify it, recheck clean HEAD/refs and use non-overwriting File.Move. Remove only a generated temporary file on failure; never recursively delete directories.
- Scope: include HEAD plus local branches, remote-tracking refs and tags; exclude stash/tool-private refs and raw .git configuration/credentials. Git bundles preserve committed history, not ignored/untracked files, editor buffers, account secrets, application databases or application backups. This is not a secret scanner or a guarantee that old commits never contained private material. Reviewed source history is a prerequisite; Git ignore rules prevent ordinary accidental additions.
- Limits: conservative link rejection means even benign aliases must use their direct paths. User-controlled backup directories must not be concurrently changed; this is a development recovery tool, not an adversarial multi-user filesystem sandbox. On-device independent backup plus authorized remote Git reduces source-loss risk but is not off-device protection for local private data.
- Verification: plain PowerShell synthetic fixture runner checks real Git bundles, restore HEAD/tree, tags/branches, dirty-source refusal, no overwrite, path/link rejection and corrupt/missing bundle handling. Test fixtures are retained outside the repository. Actual source clone/restore and CI outcomes are recorded separately in M0 evidence.

Logs/checkpoint labels are fixed safe strings and never include source text, credentials or filesystem errors.
- HTTP accepts no destination paths. Browser downloads verify the whole artifact hash before publishing a Blob. The scoped native save command first validates ownership/completion, then opens the trusted system Save dialog; host code stages beside the chosen new filename, verifies the hash and atomically creates a hard link without overwriting existing files. Its path is never supplied by browser/renderer requests. No generic filesystem/process capability or dependency was added.
- Full application backups, schedules and product restore remain M2.5. Audited vault approval remains M2.6. Existing applied migrations and the master specification are unchanged. Tests and actual workflows, rather than this decision, determine acceptance.

M2.4 recovery refinement: native Save dialogs monitor the actual Rust parent process and terminate if it exits; renderer requests cannot supply that PID or a destination. The verifier tests a pending dialog during desktop termination before its separate owned-child cleanup. Worker notification and shutdown decisions share one synchronized pending-root queue, so headless requests cannot lose a wake-up. These refinements passed the final M2.4 workflow, including actual dialog parent termination and bounded owned-process cleanup; publication evidence follows its ledger.

## ADR-0021: M2.5 scoped snapshots, schedule consent and fresh recovery

User continuation authorizes completing M2.5 only; vault/crypto code is excluded. Preserve applied migrations and the master specification. Schema 8 is a forward compatibility barrier with schedule consent, bounded upload tracking and restore-origin IDs.

Workspace packages contain a newly constructed constrained SQLite catalog, exactly referenced immutable Markdown revisions, schema/scope descriptor and integrity manifest. This avoids deleted-page leakage from filtering a copied full catalog. A separate all-workspaces application scope uses the [SQLite online backup API](https://www.sqlite.org/backup.html) and includes completed job artifacts. Schedules in recovered application catalogs are disabled; incomplete jobs are Paused. Private plaintext, local-disk destination and retained versions require explicit consent. Sealed remains refused and ordinary packages contain no credential material.

Backups reuse six-state jobs, the single process worker, owner leases/checkpoints and managed immutable artifact retrieval. Package verification and final privacy/owner checks precede publication. Cancel/retry/restart rebuilds an idempotent snapshot, retaining unreferenced private staging on failure. Scheduling defaults off, runs only inside a host process, atomically advances due-time and enqueues once across competing processes, records missed intervals and never prunes.

Saved archives enter through bounded 64 KiB owned upload chunks, with a 256 MiB artifact limit and eight incomplete uploads per workspace. Strict USTAR parsing rejects links/extensions/duplicates/traversal; exact catalog schema, foreign keys, known versions, referenced members, hashes and domain fields are validated before import. Restore is always fresh workspace IDs, remapped records/revisions/relationships/jobs and retained source identity mappings. File sync precedes catalog commit; originals are not reset, overwritten or automatically purged. Hashes detect corruption, not malicious tampering by an owner who can rewrite both catalog and archives.

The earlier generic JSON catalog and directory-copy helper were development groundwork, not a verified application recovery flow. M2.5 acceptance is recorded only after real SQLite assembly and actual browser/native workflows. [Evidence](evidence/M2-5.md) records executed checks and remaining work; this decision alone does not certify M2.
