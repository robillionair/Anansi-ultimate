## Foundation setup and verification

Use Git, Node and exactly pnpm 11.25.0 (ADR-0006). No runtime or development package dependencies are required yet. The lockfile is generated by pnpm for the real empty workspace. Corepack is optional; if the project pin is not honored by your shell wrapper, check `pnpm --version` and use an explicitly versioned invocation instead. Do not change global installations implicitly.

~~~powershell
git status --short
git pull --ff-only
node --version
pnpm --version
pnpm install --frozen-lockfile --ignore-scripts
node --test tests/repository-hygiene.test.mjs
node scripts/validate-planning.mjs --self-test
git diff --check
git hash-object docs/MASTER_SPEC.md
~~~

The version command must report 11.25.0 before lockfile operations. If absent, `npm exec --yes --package=pnpm@11.25.0 -- pnpm --version` and the same prefix with `install --frozen-lockfile --ignore-scripts` select an exact package without editing the global installation. This fallback is documented, not exercised in this environment. Resolve new dependencies only in an approved task and commit the manager-generated lockfile. Lifecycle scripts are disabled for foundation installs; revisit approved dependency build requirements when real packages are introduced.

Root `pnpm check` / `pnpm check:docs` validate documentation, state and evidence paths; `pnpm test` runs all foundation tests and `pnpm test:docs` runs documentation fixtures. `pnpm build` builds the browser production target. `pnpm backup:source -Destination <absolute-new-bundle-path>` creates and verifies an independent source backup from a clean committed checkout; `pnpm test:backup` runs the PowerShell safeguard/restore checks. See RECOVERY_AND_BACKUP.md for required parent paths and limits. The legacy validate-planning entrypoint delegates to validate-docs and preserves its self-test. Foundation CI runs Windows/Linux using exact Node/pnpm versions, SHA-pinned actions and contents:read permission. M1.2 adds actual Rust tests, generated-contract checks, frontend builds and browser workflows to CI.

## Directory and contract ownership

The directories below are future implementation ownership boundaries, not generated packages:

| Path | Responsibility |
|---|---|
| apps/desktop | Tauri command transport and explicitly scoped native capabilities |
| apps/web | Browser UI entrypoint and authenticated HTTP transport; no native APIs |
| crates/core | Shared domain operations, validation, authorization, persistence rules |
| crates/api | Authenticated local HTTP adapter invoking the same core operations |
| packages/contracts | Single authoritative DTO/schema contract or generated bindings; no parallel handwritten native/browser business rules |
| packages/ui | Shared accessible components, design tokens and domain client interfaces |
| tests | Cross-layer/acceptance fixtures and foundation tests, with synthetic data only |
| scripts | Tracked development tools; required scripts must not exist exclusively under .git |

M1.2 selects Rust serde DTOs, schemars schemas, generated TypeScript/static Ajv validators and verifies readiness transport parity. Commands validate external DTOs, then invoke core authorization/domain operations. Desktop privilege stays behind scoped Tauri capabilities. The browser readiness adapter requires authentication and exact Origin/Host checks; no filesystem/process operations are exposed. M0.1 established ownership only; database schema, vector index and provider designs still belong to their later tasks.

## Repository policies

Text defaults to UTF-8 and LF; Windows .cmd/.bat use CRLF via attributes. Binary assets stay binary. Existing history/master content is preserved; do not run bulk renormalization. EditorConfig uses two spaces, with four for Rust, and preserves intentional Markdown trailing spaces.

Keep real user workspaces under ignored root workspaces/local-data directories or outside the repository. Root backups/artifacts, database files, private keys, credentials, local npm configuration and environment files are ignored. Safe `.env.example`/`.env.*.example`, source, lockfiles and synthetic Markdown/JSON/SQL fixtures stay trackable. Database binary fixtures are deliberately ignored: prefer synthetic JSON/SQL generation inputs; any future binary fixture exception requires review. Ignore rules are prevention, not secret scanning or encryption; never force-add secrets or real memories. Root scripts must stay in tracked scripts, never in an ignored data directory.

The state file records task completion, the next task and the prior verified checkpoint. A following metadata commit records a newly published checkpoint to avoid embedding a commit's own SHA. See [recovery](RECOVERY.md). M0 verification evidence includes actual CI/protection and independent source restore. New milestones require new tested checkpoints and backups.

## Publishing after M0.2

Master requires both Foundation checks with admin enforcement and no force push/deletion. Publish a codex/ task branch first and wait for both checks on its exact commit. Fast-forward master only with that checked SHA; never bypass or disable protection. If branch rules require a pull request, create one and merge only after required checks pass. Keep commits based on current master to satisfy strict checks. All status/evidence changes are checked too. An administrator can inspect the actual settings at the repository branch settings page; any future permissions failure remains an explicit blocker.

The current validator intentionally supports repository Markdown inline/image/reference links and GitHub-style heading fragments outside fenced/inline code. Use simple Markdown links; it is not a full renderer. State validation checks required keys, milestone/task IDs, SHA format, plan/evidence existence and blocker structure; tests separately verify the checkpoint exists in Git history.

## M1.2 commands and local pairing

Install pinned dependencies with `pnpm install --frozen-lockfile --ignore-scripts`. The tracked cargo wrapper finds CARGO_HOME/default user-local Rust without modifying global PATH.

- `pnpm contracts:generate` regenerates schemas, declarations and static validators from Rust; `pnpm contracts:check` rejects drift.
- `pnpm typecheck`, `pnpm test:ui`, `pnpm test:rust` verify types, contract client and Rust workspace. Run `node scripts/cargo.mjs fmt --all --check` and `node scripts/cargo.mjs clippy --workspace --all-targets --locked -- -D warnings`.
- `pnpm build:web` (also root build) creates apps/web/dist. `pnpm dev:web` serves the browser on http://127.0.0.1:1420; `pnpm --filter @anansi/web preview` serves the production build there.
- In another terminal, `pnpm dev:api` starts the authenticated loopback service on 127.0.0.1:1451. Open the private pairing.json path printed by that process with your own local editor, and copy its token to the browser pairing form. Do not paste it into chat, commands, URLs or logs. API startup never prints the token. Leave the process running; Ctrl+C exits gracefully and removes its session file. A restart requires pairing with the new token. A forced kill can leave an owner-only stale file; its token no longer authorizes a new session.
- `pnpm dev:desktop` runs Tauri against a separately running dev:web. `pnpm build:desktop` builds the real Windows application without bundling an installer. The bundled application calls Rust directly and needs no API process or browser token. Native runs need the verified MSVC/WebView2 toolchain.
- For a repeatable bundled debug test: `pnpm build:web`, then `node scripts/cargo.mjs build -p anansi-desktop --features custom-protocol --locked`, then `node scripts/verify-desktop.mjs`. The verifier launches the real application and attaches test-only CDP; it closes the window on completion. For an elevated CI host, use `node scripts/build-desktop-test.mjs` and `node scripts/verify-desktop.mjs --configured-cdp`: the debug-only build injects the argument through the WebView2 API because elevated hosts ignore environment overrides. Normal product/release configuration has no CDP argument; do not distribute the debug test artifact.
- Before `pnpm test:e2e`, build the web and API: `pnpm build:web`, `node scripts/cargo.mjs build -p anansi-api --locked`, `pnpm exec playwright install chromium`. Tests start production preview on 1420 and an isolated API with a random port/private external temp pairing directory. Keep port 1420 free. They remove their synthetic session files; no real user data is used. Screenshots under ignored test-results show real connected views after the password input is gone. Traces are disabled to avoid retaining credentials.

The only domain operation is readiness. No workspace, setting, memory, provider or installer capability is implied. Use [M1.2 evidence](evidence/M1-2.md) for actually executed checks and [the plan](../plans/PHASE-001-runnable-shell.md) for remaining tasks.
