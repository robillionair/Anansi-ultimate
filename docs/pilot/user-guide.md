# ANANSI v1 pilot — first-time-user guide

ANANSI is a local-first intelligence workspace. Your
notes, documents, and projects stay on your computer.
AI features use a local model or a provider you
configure yourself; nothing is sent anywhere without
your setup and, for paid use, your explicit permission
and budget.

This is a development preview, not a
production-certified release. Use synthetic or
non-important data first. Read the
[limitations and privacy sheet](limitations-and-privacy.md)
before you put anything real into ANANSI. If
something goes wrong, see
[troubleshooting](troubleshooting.md). To report a
problem, use the
[bug-report template](bug-report-template.md).

What this guide covers: installation, creating a
workspace and a project, setting up a local model or
a desktop API key, importing a document, searching,
asking with citations, and backing up and restoring.
It covers the pilot workflows only; the full
evidence-backed scope is the
[pilot scope](../handoffs/v1-pilot-scope.md).

## Before you start

You need:

- The installer file you were given, plus its
  accompanying `packaging.json` identity file. Keep
  them together. The app itself shows only version
  `0.1.0`; the `packaging.json` file is what
  identifies the exact build you are running. You
  will need its `gitCommit` value and the installer
  hash for any bug report.
- A Windows x64 computer. The installer is
  per-user and English-only.
- Synthetic test material: a short `.txt` or `.md`
  file, and optionally a small text-layer PDF or
  DOCX. Do not use real secrets or irreplaceable
  data.
- Optional, for local AI: Ollama or LM Studio
  already installed, with a model already pulled
  or downloaded. ANANSI never downloads a model
  for you.
- Optional, for cloud AI: an API key for a
  provider you use. Key setup works in the desktop
  app only, never in a browser session.

## 1. Install

1. Double-click the installer
   (`ANANSI Ultimate_0.1.0_x64-setup.exe`).
2. Expect a Windows SmartScreen or reputation
   prompt: this is an unsigned development build.
   Record exactly what appears. Proceed only if
   you were given this build directly by the pilot
   organizer.
3. Install to the default per-user location and
   launch ANANSI.
4. If the computer has no WebView2 runtime, the
   installer embeds the WebView2 bootstrapper and
   needs internet access to install the runtime.
   That is the only network use during
   installation.

If you were given browser access instead of the
installer: open the address you were given, and on
the Core connection screen enter the Local API
address and the Session token from the private
pairing file provided by the local service on the
same computer, then choose Connect to core. The
token stays in the tab's memory and is forgotten on
reload. Never share the pairing file or the token.

To confirm which build is running, open Connection
and read the Core connection panel: Application,
Core version, Operating system, Core uptime,
Contract version, Application version, and API
version. Those values alone cannot distinguish one
pilot build from another; always cite the
`packaging.json` identity in reports.

## 2. Create a workspace

First launch walks you through four steps:

1. **Choose your starting point.** Pick one of the
   five intents (for example, Explore ANANSI).
   Your choice does not start an AI task, and you
   can change it later in Settings. Choose
   Continue to workspace.
2. **Create or reopen a workspace.** Enter a New
   workspace name (1–64 ASCII letters, numbers,
   spaces, underscores, or hyphens; start with a
   letter or number) and choose Create workspace.
3. **Review your privacy.** Read "Your privacy,
   plainly": storage is plaintext, this is not an
   encrypted vault, backups are not automatic, and
   continuing does not authorize cloud sharing,
   model downloads, or recording of drafts. Tick
   "I have reviewed these privacy limits" and
   choose Continue to AI setup.
4. **Choose AI setup.** No AI setup is required.
   Choose Skip AI setup and enter ANANSI to start
   without AI, or set up AI later from Local
   Models or AI Providers. Nothing is downloaded
   or generated by continuing.

You land on the Dashboard. To reopen a workspace
later, choose Existing workspace, pick its name,
and choose Open workspace. To leave a workspace
open in the app but switch away, use Close
workspace on the workspace screen.

## 3. Create a project and a note

Projects group your work. Memories and notes hold
your knowledge. All three stay in the current
workspace.

To create a project:

1. Open Projects, then choose New project.
2. Enter a Project title and Description &
   objectives.
3. Choose Save project. The project appears in the
   project list.

To save a note:

1. Open Memory (for a memory) or Notes (for a
   note).
2. Choose New memory (or New note).
3. Enter a Memory title and Memory text. Text is
   literal Markdown, up to 256 KiB. Images, links,
   and HTML are not executed.
4. Leave Privacy classification on Private unless
   you have a reason to change it. Private,
   Standard, and Public labels do not encrypt
   anything and do not publish anything. Sealed is
   shown disabled ("Sealed — vault unavailable"):
   there is no encrypted vault in this pilot.
5. Choose Save memory (or Save note). The saved
   record shows its revision number, privacy, and
   status. New records start as Proposed.

Empty states are normal: a fresh workspace shows
"No saved memories on this page." and "No imported
documents yet." until you add something.

## 4. Set up AI (optional)

Skip this section if you only want notes, search,
and documents. AI setup is never required to use
your workspace.

### 4a. Local model

1. Start Ollama or LM Studio on the same computer
   first, with a model already installed.
2. Open Local Models. The System Capability &
   Hardware Profile section shows your CPU, RAM,
   storage, and graphics. Choose Re-probe System
   to refresh it.
3. Under Detected Local AI Runtimes, find your
   runtime (Ollama Local Engine or LM Studio
   Server). Its badge reads Active, Offline, or
   Unsupported. An Active runtime lists its
   Installed Models. If no models are listed, the
   message reads "No models currently loaded. Pull
   or download a model to begin." — do that in
   Ollama or LM Studio, then re-probe.
4. To probe another local server, use Add Custom
   Loopback Endpoint. Only loopback addresses
   (`http://127.0.0.1:...`, `localhost`, or `[::1]`)
   are accepted. ANANSI connects only to local
   loopback inference servers from this screen.

Note the exact model name (tag) shown, including
any `:tag` suffix. Ask ANANSI needs the full tag;
a bare model name without its tag may not match
the runtime's model list.

### 4b. Desktop API-key setup (Connect AI)

This works in the desktop app only. In a paired
browser session, credential setup is refused with
a direction to use the desktop app. Never type a
key into a web form: ANANSI never asks for one
there.

1. Open AI Providers. Under the provider catalog,
   pick a provider to start the Connect AI flow.
   Connecting adds one provider at a time and
   never replaces providers or budgets you already
   configured.
2. **Step 2 — Endpoint.** Check the Base URL. The
   backend derives Locality (local or cloud) from
   the endpoint; a configuration claiming
   otherwise is rejected. Leave Advanced settings
   alone unless you were told to use a custom
   endpoint. Choose Continue.
3. **Step 3 — Credential setup.** Choose Generate
   reference to create a credential reference
   (the OS keyring account label). Then choose Set
   credential (native prompt): the trusted native
   Windows credential prompt opens. Paste your key
   there. The key moves from the prompt into the
   operating system credential store and is never
   typed into, or sent through, the app page.
   Choose Check status to confirm it reads
   "present in the OS store". If you change your
   mind, Discard draft leaves the setup without
   saving; a stored-but-unsaved key appears later
   under Unused credentials, where Remove unused
   key deletes it from the OS store.
4. **Step 4 — Choose a model.** Enter the model id
   exactly as the provider names it. A new model
   starts cost-unknown, and unknown is treated as
   paid: the Zero-Cost Lock blocks it until it is
   verified free or a paid permit is issued.
   ANANSI never assumes an unverified model is
   free.
5. **Step 5 — Review and save.** Check the
   provider, endpoint, credential, and models,
   then choose Save connection. Saving makes no
   inference calls; the connection is verified on
   your first authorized use.

The Zero-Cost Lock is on by default: paid
candidates are refused until verified free or
covered by a paid permit. Leave it on unless you
explicitly intend paid use with a budget.

There is no "Continue with ChatGPT" sign-in in
this pilot. It is deferred and disabled; if you
see a control with that name, report it as a
defect with your build identity.

## 5. Import a document

1. Open Documents and choose "Choose a .txt, .md,
   .pdf or .docx file". Only those four formats
   are supported. A PDF must have a text layer;
   scanned or image-only PDFs need OCR, which is
   not in this pilot.
2. In Review import, check the file name, byte
   count, and (for text files) character count.
   The SHA-256 of the file as picked is shown; the
   server re-verifies it before the import runs,
   and a changed file is refused.
3. Choose a Privacy classification (Private is
   the default) and optionally a Project, then
   choose Import document. Or choose Discard to
   drop the import before anything is sent.
4. Watch Import progress: the job moves through
   Queued, Running, and Completed. Use Refresh
   import to update it. Use Cancel import to stop
   it; a cancelled import publishes no document.
   If an upload is interrupted (for example, the
   browser was closed), it appears under
   Interrupted uploads: pick the same file again
   and choose Resume upload — completed parts are
   not re-sent.

Size limits are per format: text and Markdown
files up to 65,536 bytes with text up to 8,000
characters; PDF and DOCX files up to 1,048,576
bytes (1 MiB) with extracted text up to 32,000
characters. Oversized, empty, unsupported, and
invalid-encoding files are refused with a message
naming the problem; see
[troubleshooting](troubleshooting.md).

Imported documents appear under Imported
documents. Open one to read it; PDF results name
the page, DOCX results name the heading section.

## 6. Search

1. Open Search. The default mode is Title only,
   which searches record titles only. For
   full-text search, choose Full-body search
   (includes Markdown text).
2. Enter a Search query and choose Search
   knowledge (full-body) or Search titles (title
   mode). Title search requires all words to
   match. Full-body search supports keywords,
   exact phrases in quotes, and prefix wildcards.
3. Optionally narrow by Record type, or tick
   Include archived search results / Include
   expired search results.
4. Results list matching records. Choose one to
   open it. "No matching records. Try different
   words or filters." means nothing matched; it
   is not an error.

Title and full-body search send nothing to an AI
provider. Sealed records are always excluded.
Hybrid semantic search is a separate mode that
needs a local embedding model and Index workspace
embeddings first; it fuses keyword and vector
results and is bounded to the top 100 records.

Tip: search uses single words best. Hyphenated
terms may match nothing; try one distinctive word
from the document instead.

## 7. Ask with citations

Ask ANANSI answers strictly from your saved
workspace memories, notes, and records, using a
local loopback runtime (Ollama / LM Studio). It
does not use cloud providers from this view.

1. Open Ask ANANSI.
2. Enter the Installed Ollama model (full tag,
   including the `:tag` suffix), the Local
   inference endpoint (for example,
   `http://127.0.0.1:11434`), and Your Question
   (up to 500 characters). The Embedding model
   for semantic grounding is optional.
3. Choose Ask Question. While it runs, Cancel
   generation stops it.
4. Read the status banner:
   - ANSWERED: generated from workspace evidence.
     Check the cited sources; citations do not
     guarantee correctness.
   - OFFLINE: "Local AI runtime is offline.
     Grounded context compiled below." The
     compiled citations are still shown; no
     answer was invented. Start your runtime and
     ask again.
   - INSUFFICIENTEVIDENCE: "No relevant memories
     found in this workspace." Add or import
     relevant material and ask again.
5. Check Grounded Citations: each citation names
   its source, section heading, and line number,
   with a snippet.
6. Choose View What ANANSI Sent (Disclosure) to
   see the Context Disclosure Manifest: runtime,
   model, character count, estimated tokens,
   routing reason, source titles, and the exact
   compiled prompt sent to the local model.

Ask uses a 4,000-character context budget: only
the most relevant evidence is compiled into the
prompt. If an answer misses material you expected,
narrow the question or check that the material is
searchable first (section 6).

## 8. Back up and restore

Backups are plaintext snapshots. Treat backup
files as data-bearing: anyone who can read the
file can read its contents. Sealed records and
credentials are refused from backups.

To create a backup:

1. Open Backups ("Back up and recover").
2. Tick "I consent to a plaintext copy of the
   selected workspace and its history in private
   managed storage." The Create backup button
   stays disabled until you consent. Optionally
   tick Application data backup to include all
   workspaces, settings, history, and completed
   job artifacts.
3. Choose Create backup. The backup runs as a job;
   choose Refresh backups to check it.
4. To save a backup file outside the app, open
   Jobs and export, find the Completed backup
   job, and choose Save complete export (desktop)
   or Download complete export (browser). The
   download is verified against its SHA-256
   before it is published; keep the file
   somewhere safe. A backup on the same disk
   cannot protect against losing that disk.

To restore a saved backup file:

1. From a workspace (a new local workspace after
   recovering or replacing your computer), open
   Backups.
2. Tick the plaintext consent checkbox, choose the
   Saved backup file (a `.tar` file, up to
   256 MiB), and choose Import saved backup.
   Import verifies every member before the backup
   becomes available for preview. An invalid
   archive is refused.
3. When the import job is Completed, choose
   Preview restore. The Verified restore preview
   shows the workspace name, schema version,
   workspace/record/revision/relationship counts,
   total bytes, privacy summary, SHA-256, and
   conflicts. Check the counts against what you
   expect.
4. Enter a Restored workspace name, tick "Restore
   into fresh workspace IDs and preserve all
   original workspaces.", and choose Restore
   verified backup. Restore creates fresh IDs;
   original workspaces are preserved.
5. Reopen the restored workspace from Workspace
   (Existing workspace) and verify your documents
   and search work there.

Scheduled backups are off by default. Under
Scheduled workspace backups you can enable
hourly, daily, or weekly snapshots; they run only
while the desktop app or local API is open,
missed intervals are reported, and all versions
are retained with no automatic deletion.
Restored schedules start disabled.

## 9. Restart and reopen

Close ANANSI and reopen it: your workspaces,
projects, documents, and search results persist.
An in-flight job resumes or parks truthfully
after a restart; it never silently reports
Completed. If a job looks stuck after a restart,
see [troubleshooting](troubleshooting.md).

## Do and do not

Do:

- Use synthetic or non-important data.
- Keep the installer and its `packaging.json`
  together, and cite both in bug reports.
- Check citations and the disclosure manifest
  before trusting an AI answer.
- Take a backup before trying anything you cannot
  afford to lose, and keep the backup file
  somewhere safe.

Do not:

- Use real secrets, passwords, or irreplaceable
  data.
- Expect ChatGPT sign-in: it is not in this pilot.
- Expect generated code to run: Product Forge
  exports source for review only, and ANANSI
  never builds, tests, previews, or deploys it.
- Share backup or export files as if they were
  encrypted: they are plaintext.
- Share API keys, pairing tokens, or private
  documents in bug reports or screenshots.
